# 使用指南

本文档对应 CDK Redeem Only `2.2.0`。版本号以 `manifest.json` 为准。

## 安装与更新

1. 解压 GitHub Release 包。
2. 打开 `chrome://extensions/` 并开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择解压目录。
4. 如需在无痕窗口运行，进入扩展详情并开启“在无痕模式下启用”。
5. 更新扩展后先在管理页点击“重新加载”，再重新打开侧栏。

源码目录适合开发调试；日常使用优先加载 Release 中的脱敏包。

## 必填配置

### 邮箱 Provider

按实际使用的邮箱来源填写对应配置。Hotmail、2925、iCloud、Gmail 和自定义邮箱分别由自己的 Provider 处理；不要把一个 Provider 的密码、验证码地址或会话配置复制到另一个 Provider。

自定义邮箱池支持保存取件地址。自动运行只会选择尚未注册、未被封存并且当前可用的邮箱。

### 兑换配置

- `UPI Key`：填写后端提供的外部 API Key，只填 Key 本身。
- `UPI Client ID`：可以留空，扩展会生成并保存在浏览器本地。
- `UPI 卡密池`、`IDEAL 卡密池`、`PIX 卡密池`：一行一个 CDK，三个池互不覆盖。
- `兑换轮数`：限制一次批处理的总轮数；`0` 表示只执行首轮。
- `操作间延迟`：页面较慢或按钮经常未就绪时再开启。

CDK 导入只更新对应渠道的池和状态。自动注册主流程是否立即提交兑换，由当前运行模式、资格结果和渠道可用性共同决定。

## 自动注册流程

当前主流程为七步：

1. 选择或获取注册邮箱。
2. 打开 ChatGPT 认证入口并提交邮箱。
3. 设置注册密码。
4. 获取并提交邮箱验证码。
5. 填写账号资料。
6. 完成账号注册和密码设置恢复流程。
7. 按所选路线处理 2FA/Passkey、读取 AT、检查试用资格并决定是否进入 Free。

如果步骤 3 提交密码后进入已有账号的 TOTP 二次验证页，扩展会在侧边栏流程中显示“步骤 3.5：已有账号 2FA 登录（按需）”，并执行条件式登录。该行只是状态提示，不能单独点击或跳过。只有当前邮箱已有本地 TOTP 密钥时才会自动登录；步骤 3.5 处理期间不会再把页面最初返回的“账号已存在”提前当作本轮失败，只有后台确认最终结果后才更新流程。登录成功后不再获取注册验证码，并跳过注册资料页。缺少密钥时继续按“账号已注册”处理；动态码失败或页面状态未知时保留当前认证页，不删除账号、不清 Cookie、不切换邮箱。普通日志不会显示 TOTP 密钥或六位动态码。

只有明确的 `eligible=true` 和完整成功证据才能把账号归入 Free。以下结果都不能直接当作无资格或 Token 无效：

- 网络错误、超时、HTML 错误页或服务端 5xx；
- 资格字段缺失或返回结构未知；
- 查询账号与返回账号不一致；
- CDK 远端状态尚未确认。

免 2FA 路线不会因为没有 TOTP Secret 而被排除；它使用自己的凭据格式和恢复标记。

## 账号与分组

### Free

Free 保存已明确具备试用资格、但尚未确认对应渠道 Plus 的账号。支持：

- 导入、导出和删除；
- 登录及补充/刷新 AT；
- 会员识别；
- 单账号或批量 UPI、IDEAL、PIX 兑换；
- 按用户选择的一个渠道执行“一键兑换全部”。

网络异常或远端结果未知时账号保留在 Free，并记录真实原因。

### Plus

只有远端兑换成功并且会员状态得到确认后，账号才进入对应渠道 Plus。UPI Plus、IDEAL Plus 和 PIX Plus 的状态及删除记录相互独立。

删除某个渠道的 Plus 记录只删除该渠道投影，不应删除其他渠道状态或统一账号凭据。

### 删除与恢复

删除分组记录会写入 tombstone，避免旧状态刷新后把记录重新显示。重新导入、重新查询或明确提交新操作时，系统才会按对应规则解除相关 tombstone。

## CDK 兑换安全规则

1. 每个账号、渠道和 CDK 使用独立资源锁。
2. 提交前先写入副作用账本和幂等键。
3. `prepared` 尚未发出请求时可以安全恢复。
4. `dispatched`、`unknown` 或结果不完整时只能查询原请求。
5. 只有明确 `confirmed` 或明确失败结果才能终结任务并释放相应锁。
6. 远端结果无法确认时进入人工处理，不自动换 CDK 或重复提交。
7. 网络错误不能直接解释为 Token 无效；只有明确的认证失效证据才能清除或替换 AT。

UPI、IDEAL、PIX 的失败次数和每日限制分别计算。一个渠道失败不能覆盖另一个渠道的可用状态。

## 导入与导出

### Free 文本

带 2FA 的常用格式：

```text
邮箱---密码---2fa---at---时间戳
```

免 2FA 的常用格式：

```text
邮箱---取件地址---at---时间戳
```

Free 导出可以选择是否包含取件地址。导出会合并统一账号模型和兼容数据，避免只导出旧结果表而漏掉免 2FA 账号。

### Plus 文本

```text
邮箱----密码---2fa---时间戳
```

Plus 文本不包含完整 AT。

### 配置备份

- 普通导出：使用安全格式，排除密码、完整 AT、2FA Secret、Cookie、API Key 和完整 CDK。
- 敏感备份：用于完整迁移，必须在界面二次确认，并标记 `exportMode: sensitive`。
- 导入：先识别 schema 版本，再保存最多三份受限导入前备份；旧版数据会幂等迁移，不能通过清空旧数据来简化升级。

导出文件只能恢复其实际包含的数据。普通安全导出可以恢复脱敏账号明细和分组，但不会凭空恢复被排除的密码或完整 Token。

## 任务、停止与恢复

注册、AT 刷新、会员核验和 CDK 兑换都会创建持久任务及隔离事件。Service Worker 重启后按照 checkpoint 恢复：

- 未发生外部副作用的步骤可以安全继续；
- 已发出远端请求的步骤只查询原请求；
- 无法证明安全的步骤停止并等待人工处理；
- 用户主动停止后不再回放上一轮日志，也不会继续调度新步骤。

第 4 步和第 6 步恢复会优先保留当前邮箱、标签页和注册现场。恢复次数耗尽后停止，不返回步骤 1 清 Cookie 重注册。

第 4 步已经进入邮箱验证码路由、但验证码输入框仍在延迟渲染时，会先使用本步骤 75 秒总观察时间。预算耗尽但路由仍明确是邮箱验证码页时，自动运行会保留当前标签页、邮箱、Cookie、注册会话和当前尝试，倒计时 15 秒后只继续 `fetch-signup-code`，不会回到步骤 1。该同节点续等最多 3 次；仍未出现输入框时才保留现场停止，供人工检查。

第 5 步提交资料后若出现 “Try again”，页面可能重新创建并清空姓名、年龄输入框。后台复核会沿用本轮生成的资料在当前页面重新填写后再提交，最多 3 次；字段不完整时始终禁止提交空表单，也不会因此清 Cookie 或换邮箱重注册。

第 6 步在 ChatGPT“Security and login”弹窗中会识别普通文本节点组成的 Password 设置行，包括 `Password / Add / 箭头` 没有原生按钮角色的新版布局。入口点击后仍以 URL、验证码页或页面状态变化确认结果；首次观察窗口内仍未跳转时，会在同一标签页继续复核最多 45 秒，不立即消耗重启次数。仍无法确认时才进入受限恢复并保留现场。

Security 设置页已经打开、但 Password 行仍在延迟渲染时，第 6 步会先保留当前标签页再等待最多 45 秒，不会在第一次 25 秒等待结束后立即刷新页面。只有同页复核仍找不到入口时，才执行既有的有限步骤 6 重启。

## 失败诊断

打开顶部“配置”菜单，点击“导出最近一次失败诊断”。诊断 JSON 会直接写入剪贴板，并提示“已导出至剪贴板”。

诊断包括：

- 最近一次真实错误；
- 错误前后最多各 100 条日志；
- 当前 URL、工作流和认证页面状态；
- 验证码输入框检测结果。

当前运行直接产生的错误优先作为诊断主故障。停止时追加的“快照”旧错误只在没有当前直接错误时兜底，不会覆盖本轮真实故障。

诊断不会包含验证码、密码、完整 AT、Cookie、API Key、完整 CDK、完整邮箱或敏感 URL 参数。

## 常见问题

### 导入后没有 Free 或邮箱

先确认导出类型。安全配置不会包含被明确排除的凭据；旧版 summary-only 文件也不能恢复不存在的账号明细。优先使用当前版本重新导出的配置或明确确认的敏感备份。

### Free 导出数量少于界面数量

确认账号是否真的被明确归类为 Free，以及当前“包含取件地址”开关。没有 AT、只有邮箱池记录、状态未知或被删除的账号不会伪装成可导出的 Free。

### HTTP 401/403 或 Token 错误

检查外部 API Key 和接口权限。空响应、网络失败或普通 403 不能统一解释成 ChatGPT AT 无效；以诊断中的结构化错误码为准。

### CDK 一直等待

等待、处理中和未知状态不会自动重新提交。先刷新原远端任务；只有明确失败且策略允许时才能进行下一次安全尝试。

### 修改代码后行为没有变化

回到 `chrome://extensions/` 重新加载扩展，并重新打开侧栏。Background 修改后必须让 MV3 Service Worker 重新启动。
